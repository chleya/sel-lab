## 二、四层结构详解

### 第一层: 目标定义 (Goal Layer)

**来源**: PROJECT_MANIFESTO.md

| 组件 | 内容 | 示例 |
|------|------|------|
| 研究问题 | 要解决什么问题？ | DFA能否替代BP？ |
| 核心假设 | 具体假设是什么？ | 前向学习可实现智能 |
| 成功标准 | 5个SC (Success Criteria) | SC-1 到 SC-5 |
| Phases | P0-P3 阶段划分 | 分析→学习→演化→积累 |

**5个成功标准模板**:

```
SC-1: [Locality] 变化保持局部
SC-2: [Reusability] 可复用结构涌现
SC-3: [Efficiency] 学习成本降低
SC-4: [Stability] 扰动下稳定
SC-5: [Forward-only] 无反向传播
```

### 第二层: 方法论 (Method Layer)

**来源**: METHODOLOGY.md

| 阶段 | 目标 | 产出 |
|------|------|------|
| 假设验证 | 快速验证可行性 | 基线对比 |
| 机制探索 | 找关键机制 | 消融实验 |
| 边界测试 | 找适用范围 | 稳定性报告 |
| 理论提炼 | 形式化 | 命题/定理 |
| 应用拓展 | 找应用场景 | 场景验证 |

**执行原则**:
- 每次只改一个变量
- 随时记录结果
- 定期复盘调整

### 第三层: 执行循环 (Execution Layer)

**来源**: ACTION_PLAN_DETAILED.md

```
A阶段 (Assessment): 基础能力验证
  - SC-4 稳定性测试
  - 收敛性分析
  
B阶段 (Boost): 性能提升
  - B.1 更大规模数据
  - B.2 学习率优化
  - B.3 数据增强
  
C阶段 (Characterize): 理论深化
  - C.1 收敛分析
  - C.2 演化分析
  
D阶段 (Deploy): 规模扩展
  - D.1 更大模型
  - D.2 更复杂任务
```

**迭代模式**:

```
A -> B -> C -> D
│    │    │    │
│    │    │    └──► 复盘
│    │    │         │
│    │    └─────────┤
│    │              │
│    └──────────────┤
│                   │
└───────────────────┘
        ▲
        │
     回到 A
```

### 第四层: 产出与反馈 (Output Layer)

| 产出类型 | 文件格式 | 存储位置 |
|---------|---------|---------|
| 代码库 | *.py | core/ |
| 实验结果 | *.json | results/ |
| 理论文档 | *.md | docs/ |
| 复盘报告 | REVIEW.md | 项目根目录 |

## 三、完整执行流程

### 3.1 项目启动

```
步骤 1: 定义目标
  ├── 撰写 PROJECT_MANIFESTO.md
  ├── 明确5个成功标准
  └── 规划P0-P3阶段

步骤 2: 搭建框架
  ├── 创建目录结构
  ├── 初始化 METHODOLOGY.md
  └── 设置版本控制
```

### 3.2 迭代循环 (每轮)

```
┌─────────────────────────────────────────────────────────┐
│                    单轮执行流程                           │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 选择阶段 (A/B/C/D)                                  │
│     ↓                                                   │
│  2. 执行实验                                           │
│     ├── 按方法论设计实验                                │
│     ├── 记录结果到 results/                            │
│     └── 确保可复现                                     │
│     ↓                                                   │
│  3. 分析结果                                           │
│     ├── 对照成功标准                                   │
│     ├── 识别问题                                       │
│     └── 记录洞察                                       │
│     ↓                                                   │
│  4. 决策                                               │
│     ├── 继续同阶段?                                    │
│     ├── 切换到其他阶段?                                │
│     └── 进入下一轮?                                    │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 3.3 阶段切换规则

| 当前阶段 | 条件 | 切换到 |
|---------|------|--------|
| A (稳定性) | SC-4 通过 80% | B |
| B (性能) | 达到性能目标 | C |
| C (理论) | 理论框架完成 | D / 复盘 |
| D (规模) | 规模测试完成 | 复盘 |

### 3.4 复盘点

| 复盘时机 | 内容 | 输出 |
|---------|------|------|
| 阶段完成 | 该阶段成果 | 阶段总结 |
| 循环结束 | 所有阶段 | 项目复盘 |
| 项目终止 | 最终状态 | 最终报告 |

## 七、总结

### 整合优势

1. **目标驱动**: PROJECT_MANIFESTO 定义方向
2. **方法保障**: METHODOLOGY 确保质量
3. **执行有序**: ACTION_PLAN 指导行动
4. **产出完整**: THEORY/REVIEW 沉淀经验

### 使用流程

```
新项目开始:
  1. 阅读 METHODOLOGY.md 了解方法
  2. 撰写 PROJECT_MANIFESTO.md 定义目标
  3. 创建 ACTION_PLAN.md 规划步骤
  4. 执行实验，参考 METHODOLOGY
  5. 记录结果到 results/
  6. 理论提炼到 THEORY.md
  7. 项目复盘到 REVIEW.md
```
